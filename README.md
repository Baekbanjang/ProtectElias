### 한 판의 흐름

```
 상점에서 시작 ─ 시작 무기를 인벤토리에 배치
      │
      ▼
 ┌─ 전투 ───────────────────────────────────────┐
 │  인벤토리에 배치한 무기가 방어선 가까운 적부터 자동 공격 │
 │  적 처치 → 경험치 → 레벨업하면 특성 카드 1장 선택  │  ← 성장
 └──────────────────────────────────────────────┘
      │ 웨이브 종료
      ▼
 ┌─ 상점 ───────────────────────────────────────┐
 │  무기 구매 → 인벤토리에 배치 · 회전 · 강화        │  ← 배치 퍼즐
 │  "둘 다 넣고 싶은데 자리가 모자라다"              │
 └──────────────────────────────────────────────┘
      │ 반복
      ▼
 방어선이 무너지면 끝 → 남은 골드로 영구 강화 · 점수는 온라인 랭킹에 등록
```

뱀서라이크류는 레벨업 때 능력치만 고릅니다. 이 게임은 여기에 인벤토리 배치 퍼즐을 더해 **두 가지를 한 판 안에서 번갈아 고민하게 만듭니다.** 웨이브 도중에는 성장을, 웨이브가 끝나면 인벤토리 배치를 고민합니다.

## 주요 기능

### 전투
- **자동 타겟팅 · 투사체 풀링** — 사거리 안에서 방어선에 가장 가까운 적부터 조준하고, 투사체는 풀에서 재사용
- **무기 10종** — 공격 방식 4가지(일반 · 관통 · 폭발 · 소환), 무기마다 사거리가 다름. 화상 · 감전을 거는 무기도 있음
- **적 5종 + 보스 2종** — 멀리서 쏘는 드론, 터지는 폭탄 등
- **액티브 스킬** — 캐릭터 고유 스킬과 컷인 연출

### 성장
- **레벨업 특성 21종** — 등급(I · II · III)마다 카드 색이 다르고, 한 판에 한 번만 나오는 고유 특성도 있음
- **아티팩트 5종** — 인벤토리에 넣으면 효과가 적용되는 패시브 아이템
- **영구 강화 10종** — 판이 끝나면 남은 골드가 모이고, 그 골드로 다음 판을 강하게 시작

### 인벤토리
- **배치 · 회전 · 강화** — 무기마다 모양이 다르고, 같은 무기를 같은 등급끼리 겹치면 한 등급 위로 강화
- **새로고침 · 제외 · 칸 늘리기** — 상품 다시 뽑기, 원하지 않는 아이템 안 나오게 하기, 인벤토리 칸 넓히기

### 그 밖의 기능
- **온라인 랭킹** — 익명 로그인, 같은 닉네임은 쓸 수 없음, 서버를 거친 점수 제출(클라이언트 직접 쓰기 차단)
- **게임 가이드 8페이지** — 처음 시작할 때 한 번 자동으로 열리고, 타이틀 · 일시정지 화면에서 다시 볼 수 있음
- **설정** — 배경음 · 효과음 볼륨, 배속(1x · 2x · 3x), 글꼴 바꾸기
- **웹 빌드** — WebGL에서 한글 닉네임 입력 지원

## 개발 관리

1인 개발이지만 **팀 프로젝트와 같은 방식으로 일정과 이슈를 관리합니다.**

### Jira — 일정 · 이슈

```
에픽 (개발 단계)
 └─ 작업      [DUT] 기능 · [DUT 결정] 설계 결정
     └─ 하위 작업  [버그] [기능] [결정] [에셋] [조사] [환경]
```

- 이슈 117건 (2026-10-05 기준) — 에픽 7 · 작업 68 · 하위 작업 42, 그중 104건 완료
- **설명 양식 3가지로 통일** — 에픽 = 목표 · 범위 · 제외 / 작업 = 내용 · **완료 조건** · 선행 / 버그 = 상황 · 원인 · 처리 · 커밋
- 버그는 상황 · 원인 · 처리 · 커밋 양식으로 하위 작업에 기록하고, 심각도에 따라 우선순위를 표시합니다

### Confluence — 문서 · 결정

| 페이지 | 용도 |
|---|---|
| 결정 기록 | 확정된 설계 결정만 한 줄씩. **결정 · 이유 · 버린 대안 · 근거** |
| 기획·진행 허브 | 현재 단계와 다음 작업 |
| 단계 회고 | 단계가 끝날 때마다 계획과 실제의 차이, 막혔던 것, 넘긴 것 |

### 에셋 요청 관리

- 그림 에셋은 `ASSET-0xx` 번호로 요청 목록을 만들고 Jira `[에셋]` 하위 작업과 연결합니다
- 요청마다 **진행 상태 · 이 에셋을 기다리는 작업 · 공통 규격**(크기 기준 · 투명 처리 · 원본 덮어쓰기 금지 등)을 적고, 결과물은 검수한 뒤 게임에 넣습니다

### AI 도구 활용

| 역할 | 담당 |
|---|---|
| 기획 · 설계 결정 · 우선순위 · 플레이 검수 | 본인 |
| C# 구현 · Jira/Confluence 기록 | Claude Code (일부 구현 · 밸런스 시뮬레이션은 Codex) |
| 픽셀 에셋 제작 | Codex (Aseprite) |

셋이 함께 쓰는 게시판 문서에 요청 · 결과 · 남은 일을 적어 주고받습니다. 결과를 판단할 때는 **원본을 직접 확인할 수 있는 쪽만 결론을 내린다**는 원칙으로, 빠뜨리거나 잘못 판단하는 일을 줄입니다.

## 프로젝트 구조

```
Assets/Scripts/
├─ Combat/      무기 · 투사체 풀 · 타겟 탐색 · 공격 타입 · 스킬
├─ Enemy/       적 이동 · 스포너 · 보스 · 적 투사체
├─ Inventory/   그리드 판 · 아이템 · 아티팩트 · 무기 트레이
├─ Player/      스탯 · 레벨 · 골드 · 점수 · 특성 · 게임 오버
├─ System/      웨이브 · 씬 전환 · 저장 · 랭킹 서비스 · 배경음 · 배속
└─ UI/          HUD · 상점 · 레벨업 · 설정 · 가이드 · 랭킹 · 닉네임
Server/
└─ LeaderboardPolicy.ac   플레이어의 리더보드 직접 쓰기를 막는 접근 정책
```

무기 · 특성 · 아티팩트 · 강화 수치는 모두 **데이터 파일(ScriptableObject)** 로 따로 두어, 코드를 고치지 않고 밸런스를 조정합니다. 데이터 파일 자체는 에셋이라 이 저장소에는 없습니다.
